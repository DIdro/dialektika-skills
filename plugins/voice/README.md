# voice-kit — инструменты для построения своего голоса

Пакет отчуждаемый: ни корпуса, ни карт, ни ключей, ни чьих-либо личных
данных внутри нет. Всё личное живёт в каталоге `profile/`, путь к которому
задаётся конфигом, и в репозиторий пакета не попадает.

## Начинать отсюда: [METHOD.md](METHOD.md)

**[METHOD.md](METHOD.md) — методичка и точка входа.** Она написана для человека,
который не программист: терминал открывать не нужно, каждый шаг сформулирован
как задание агенту, которое можно скопировать целиком.

Этот файл (`README.md`) описывает только устройство пакета — что за файл где
лежит. Порядок работы, сборка корпуса, построение карт, обязательная вычитка и
проверка порогов — всё в `METHOD.md`.

## Что внутри

```
METHOD.md                  методичка: шаги от пустой папки до рабочего голоса
templates/                 скелеты карт с пояснениями, что в каждом разделе
  style-card.md            стилевая карта короткой формы
  articles-card.md         карта длинной формы
  banned.md                слой поправок к каталогу humanizer
tools/                     инструменты (чистый Python, без зависимостей)
  config.py                загрузка и валидация конфига, статус источников
  build_corpus.py          нарезка выгрузки канала в файлы корпуса
  stats.py                 статистики корпуса и пороги для линтера
  lint.py                  механическая часть списка запретов
  export_telegram.py       выгрузка своего Telegram-канала (необязательный путь)
  fixtures/                регрессионные тексты линтера
  tests/                   тесты
patterns/
  humanizer-patterns.md    снапшот каталога паттернов ИИ-текста (MIT, blader)
skills/
  voice/SKILL.md           три режима: clean, write, long
  voice-feedback/SKILL.md  захват правок в profile/edits/
voice.config.example.yaml  пример конфига со всеми полями
profile.example/           пустой скелет профиля + что куда класть
```

## Старт

```
cp -r profile.example profile
cp voice.config.example.yaml voice.config.yaml   # заполнить под себя
python tools/config.py                            # проверить, что видно
```

Дальше — по **[METHOD.md](METHOD.md)**, шаг за шагом: собрать корпус, посчитать
статистики, построить и **вычитать** карты, проверить пороги по своему корпусу.
`profile.example/README.md` объясняет, что за данные куда кладутся;
`METHOD.md` — что и в каком порядке делать.

```
python tools/stats.py                             # profile/stats.json
python tools/lint.py путь/к/тексту.md
```

Шаблоны карт лежат в `templates/`. Копировать в `profile/` и заполнять по
`METHOD.md`; в каждом шаблоне первой строкой стоит метка
`ШАБЛОН НЕ ЗАПОЛНЕН` — удалить её после вычитки, по ней видно незаполненную
карту.

## Скиллы

`skills/voice/` и `skills/voice-feedback/` — сами инструкции агента. Ни имён,
ни путей, ни ключей проектов в них не зашито: всё берётся из конфига.

Чтобы агент их видел, скопируйте каталоги туда, где он ищет скиллы
(`~/.claude/skills/` или `.claude/skills/` в проекте), либо положите ссылку.

`voice` требует заполненного ключа `author` и **останавливается**, если тот
пуст: писать от лица «автора вообще» — ровно то, ради ухода от чего пакет и
собран. Остальное скилл проверяет по `python tools/config.py` и честно
докладывает, какого источника фактуры нет, вместо того чтобы молча выдать текст
без фактуры.

Минимум, при котором `voice write` вообще работает: `profile/corpus/`,
`profile/stats.json`, `profile/style-card.md`, `profile/banned.md`. Источники
фактуры (`sources`) не обязательны — без них скилл напишет по одним заметкам, но
скажет об этом до написания, а не после.

## Зависимости

Никаких обязательных. `config.py`, `build_corpus.py`, `stats.py` и `lint.py`
работают на голом Python 3.9+. PyYAML используется, если установлен; иначе
включается встроенный разборщик подмножества YAML, а при желании конфиг
можно написать в JSON (`voice.config.json`, схема та же).

Telethon нужен только для `export_telegram.py` — это необязательный путь
сбора корпуса, тексты можно разложить и руками.

## Тесты

```
python -m pytest tools/tests -q
```
