# Звонок → решения и задачи

Скил для Claude Code: из транскрипта встречи достаёт решения, обещания, риски и задачи,
показывает одну карточку и ждёт вашего решения: **принять / отклонить / переразобрать с
подсказкой**. Ничего не пишет в ваши системы, пока вы не приняли.

Это текстовое ядро конвейера, который у нас разбирает рабочие звонки каждый день. Здесь то,
что переносится к вам за 15 минут: скил, промпты, схема данных и пример. Код сервера с
транскрибацией, записью Телемоста и веб-кабинетом — в
[`call-pipeline`](call-pipeline), очередь приёмки — в
[`ops-ingest`](ops-ingest).

## Что внутри

```
CASE.md                          разбор кейса: задача, устройство, путь, цифры
skills/call-debrief/
  SKILL.md                       скил: порядок разбора и карточка приёмки
  prompts/classifier.md          промпт: обещания, задачи, привязка к проекту
  prompts/knowledge.md           промпт: решения, риски, сдвиги, факты
  schema/debrief.schema.json     схема выхода разбора (для API — input_schema инструмента)
  schema/atom.schema.json        схема атома знаний для вашей базы
  examples/                      синтетический транскрипт и что получается на выходе
  context.example/               образец настроек: кто вы и какие у вас проекты
call-pipeline/                   сервер: транскрибация, запись Телемоста, веб-кабинет
ops-ingest/                      очередь приёмки и запись принятого
```

## Старт за 15 минут

**Нужно:** [Claude Code](https://docs.claude.com/en/docs/claude-code) с подпиской или
API-ключом.

1. **Установить** (2 мин). В Claude Code:
   ```
   /plugin marketplace add DIdro/dialektika-skills
   /plugin install call-debrief@dialektika
   /reload-plugins
   ```

2. **Прогнать пример** (3 мин)
   ```
   /call-debrief пример
   ```
   Claude Code может попросить разрешение прочитать папку скила: разрешите.
   Сравните карточку с `examples/output.md`. Попробуйте ответить
   `переразобрать: про CRM — отдельный проект dostavka-crm, разнеси`.

3. **Настроить под себя** (5 мин). В рабочей папке создайте:
   - `context/me.md` — ваше имя, роль, как вас называют в разговорах.
   - `context/projects.md` — ваши проекты, по строке: `ключ — название — о чём`.

   Если папка под git, добавьте `context/` и `debriefs/` в `.gitignore`, чтобы ваши данные
   не ушли в репозиторий.

4. **Свой звонок** (5 мин)
   Выгрузите расшифровку из Zoom / Телемоста / Google Meet / любого сервиса транскрибации
   в `.txt` и запустите `/call-debrief путь/к/файлу.txt`. Принятые разборы ложатся в
   `debriefs/` (`.md` для чтения, `.json` для переноса).

## Как это устроено у нас

```
запись звонка → транскрибация на своём сервере (Whisper, разметка говорящих)
             → классификатор (prompts/classifier.md) → извлечение знаний (prompts/knowledge.md)
             → очередь приёмки в вебе: принять / отклонить / переразобрать с подсказкой
             → только после «принять» — задачи на доску, знания в базу проекта
```

Скил повторяет ту же логику в одном чате: вместо очереди — карточка, вместо кнопок —
ваш ответ. Весь конвейер можно поднять у себя из
[`call-pipeline`](call-pipeline) и
[`ops-ingest`](ops-ingest).

**В цифрах** (на 18.10.2026): с июня через конвейер прошло 337 звонков, около 256 часов
записей. С сентября, когда ввели приёмку, решение по звонку занимает около минуты. Из 79
принятых звонков 59% приняты с первого раза, 30% — после смены проекта, 10% — после
переразбора с подсказкой. С одного принятого звонка в базу уходит в среднем 26 пунктов:
14 знаний и 12 задач.

## Три вещи, которые мы выучили

1. **Сначала приёмка, потом автономия.** Мы месяц давали агенту писать в базу знаний самому.
   Ошибки маршрутизации и лишние «задачи» потом приходилось вычищать задним числом — это
   вышло дороже, чем проверять до записи. Мы вернули приёмку.
2. **Единица проверки — звонок целиком.** На звонок выходит около 25 пунктов. Поатомные галочки
   на таком объёме начинают жать не глядя. Три действия на весь звонок и переразбор с
   подсказкой работают лучше.
3. **Неуверенность — в выход, а не в мусор.** Модель обязана сказать, опознала ли она вас
   среди говорящих и между какими проектами колебалась. Низкая уверенность — повод
   спросить человека, а не угадывать.

## Через API, без Claude Code

Промпты из `prompts/` — системный текст, `schema/debrief.schema.json` — `input_schema`
единственного инструмента, вызов принудительный (`tool_choice: {type: "tool", name: ...}`).
Транскрипт — в сообщении пользователя. Статичные части (промпт, список проектов) стоит
кэшировать: они одинаковые для каждого звонка.

## Ограничения

- Сам скил не транскрибирует: на вход нужен текст. Открытые транскрибаторы —
  [faster-whisper](https://github.com/SYSTRAN/faster-whisper) и
  [Whisper](https://github.com/openai/whisper), на первом работает наш сервис.
- Без разметки говорящих атрибуция «кто что обещал» заметно хуже — модель работает по смыслу.
- Если звонок записывали не вы (присланная запись), скил так и скажет: «владелец не
  опознан». Обещания такой записи — не ваши.
- Данные звонка уходят в модель. Если в разговоре есть персональные или чужие
  конфиденциальные данные, сначала обезличьте их.
