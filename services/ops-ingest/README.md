# ops-ingest

Очередь приёмки звонков. Забирает расшифровки из [call-pipeline](../call-pipeline), разбирает их
на знания и задачи и ставит в очередь. Страница «Разбор» в кабинете показывает звонок целиком, и вы
решаете: принять, отклонить, сменить проект, разнести по нескольким проектам или переразобрать с
подсказкой. До «принять» ничего никуда не записывается.

Это снимок кода нашего рабочего сервиса без истории коммитов. Разбор кейса —
[CASE.md](../../plugins/call-debrief/CASE.md).

## Что внутри

| Файл | Что это |
|---|---|
| `run.py` | Поллер: новые звонки → черновик в очереди |
| `api.py` | HTTP-API очереди для кабинета, вход по сессии call-pipeline |
| `review_actions.py` | Пять решений по звонку. Единственное место, которое пишет наружу |
| `prompt.py`, `context_prompt.py` | Промпты: обещания и проект, знания, раскладка, разнесение |
| `gate.py` | Флаги строки: проект неясен, обязательство с датой или суммой, чужая запись |
| `mionika_client.py`, `project_skeleton.py` | Запись в граф Мионики и раскладка по его узлам |
| `file_backend.py` | Режим без Мионики: проекты из файла, принятое в `.md` и `.json` |

## Куда пишется принятое

- **Мионика.** Основной режим, в нём работаем мы: атомы раскладываются по узлам проекта, а
  противоречие с уже лежащим в узле останавливает запись и просит подтверждения.
- **Файлы.** `OPS_INGEST_PROJECTS_FILE` и `OPS_INGEST_ACCEPTED_DIR`. Этот режим написан для открытой
  версии, в проде у нас не работал. Раскладки по узлам и проверки на противоречия в нём нет.

## Как развернуть

Рядом с call-pipeline, на той же машине. С нуля по этой инструкции сервис пока не разворачивали.

```bash
cd /opt/ops-ingest/ingest          # сюда — содержимое этой папки
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp deploy/env.example .env         # заполнить, комментарии внутри
cp deploy/*.service /etc/systemd/system/ && systemctl daemon-reload
PYTHONPATH=. .venv/bin/python -m ops_ingest.seed   # не разбирать старые записи при первом запуске
systemctl enable --now ops-ingest ops-ingest-api
```

В nginx кабинета уже есть блок `/ingest-api/` (`call-pipeline/deploy/nginx-web.conf`).
Очередь личная: её видит только пользователь `OPS_INGEST_OWNER_USER_ID`.

## Тесты

```bash
pip install -r requirements.txt && PYTHONPATH=. pytest tests
```
